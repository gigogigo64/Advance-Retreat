## 1. 项目定位

本地优先的 Windows 桌面小工具，用于**培养优点、抵制缺点**：

- 优点：「今天我坚持了这个优点了吗？」→ 坚持 = 打卡 ✅
- 缺点：「今天我避开了这个缺点了吗？」→ 避开 = 打卡 🛡️

配合连续天数（streak）、积分、愿望兑换等激励机制，形成正向闭环。

## 3. 功能规格

### 3.1 今日视图（默认主页）
- 日期 + 今日进度环（如 6/8）
- 🟢 优点卡片（点击=今天坚持了）/ 🔴 缺点卡片（点击=今天避开了）
- 打卡反馈：高亮 + 弹性动画 + streak 🔥
- 当日全部完成：🎉 撒花 + 满分积分
- 每条支持 emoji 图标 + 颜色 + 分类标签

### 3.2 清单管理
- 优点/缺点分开管理；名称、emoji、颜色、分类（健康/学习/社交/情绪/自定义）、目标频率（每天/每周N次/仅工作日）、开始日期、备注
- 归档保留历史数据

### 3.3 统计
- 单条：当前连续/最长连续/30天完成率/年度热力图
- 总览：趋势、最佳排行、需警惕排行
- 统计基于真实日期，无补卡

### 3.4 积分与愿望兑换
- 规则：打卡1条+2分；连续7天全勤+10分；满分日+5分（可在设置调整）
- 愿望清单：自定义奖励+所需积分；兑换扣分并留记录

### 3.5 每日一句话回顾
- 今日视图底部轻量输入框，每天一条，当日可编辑

### 3.6 提醒
- 可设提醒时间（默认21:00），到点检查未完成项→系统通知；全完成不打扰；可开关

### 3.7 数据与设置
- SQLite 于 `%APPDATA%/知进退/`；JSON 导出/导入；主题跟随系统+手动切换；强调色可选

- **积分防刷分原则（重要）**：任何"一次性奖励"（满分日、连续7天全勤）都必须**可逆**——取消打卡时扣回，重新打卡时按"对账"而非"是否已发放"判断，即比对应得净额与已发放净额、只补差额。切勿用"当日是否已有记录"判重，否则会出现撤销后无法重新发放而净亏分。
- **SQLite WAL 注意**：直接 `cp` 数据库文件会漏掉未 checkpoint 的 `-wal`，导致备份/快照不完整（读出来没有表）。备份或迁移必须同时处理 `.db`/`-wal`/`-shm`，或先做 `PRAGMA wal_checkpoint(TRUNCATE)`。

## 14. 需求定稿：缺点 Boss 智能转化（REQ-01）

**用户原话**：将坏习惯的每日坚持避开做成类似打 Boss 的形式，每次避开削弱其血量；削到 0 后应被转变为一个好习惯继续坚持；转换交给文档记录的中转站 GLM，须写好系统提示词，并给该 LLM「编辑相应条目的权限」和「工具调用范式」。

### 14.1 玩法定稿
- 每个**缺点 = 一个 Boss**，初始 HP 100；**每天成功避开 = 削弱 3 HP**（约 34 天击败）。
- 打卡（避开）样式：名称划去 + 斜切「避开」印章 + 血条按血量渐变；取消打卡回补 HP。
- HP 归零 = **击败**：进入击败态，提供「转化为好习惯」入口。
- **转化 = 创建对应好习惯 + 归档被击败的缺点**；转化后仍可恢复/撤销。

### 14.2 转化由 LLM 智能体完成（关键升级）
- 不再只是返回一段文本建议，而是让 GLM **通过工具调用直接读写应用数据**。
- 提供给 LLM 的工具（范式见第 15 节）：`list_habits` / `create_good_habit` / `update_habit` / `archive_habit` / `finish`。
- 必须使用**系统提示词**约束其行为（见 `dev/03-Boss智能转化.md` 定稿）。
- 客户端执行工具、校验参数、记录变更，并支持**一键撤销本次转化**。

### 14.3 技术与安全约定
- 请求必须走 **tauri-plugin-http**（`import { fetch } from '@tauri-apps/plugin-http'`），并在 `capabilities/default.json` 配置 URL scope；用 WebView 全局 `fetch` 会被 CORS 拦截（v0.1.0 即因此未真正生效）。
- 循环上限、参数校验、失败兜底（退化到纯文本建议 + 手填）必须齐备。
- LLM 只被授予「新增优点 / 归档缺点 / 修改条目」范围，不得删除数据。

### 14.4 验收标准
1. 缺点打卡一次 HP -3，取消回补；血条与击败态正确。
2. HP=0 后可触发转化，真实调用 GLM 并产生 `tool_calls`。
3. LLM 能新建好习惯并归档坏习惯，结果落库可在清单页看到。
4. 转化过程可视化（步骤/摘要），支持撤销回滚。
5. 断网/接口异常/模型不返回工具调用时，有明确兜底且不破坏用户数据。

## 15. 经验：数据操作型 LLM 工具调用范式（可复用）

> REQ-01 沉淀。适用于「让 LLM 直接读写本地数据」的场景。

- **协议**：OpenAI 兼容 `tools`（`type:"function"` + JSON Schema `parameters`）+ `tool_choice:"auto"`；响应取 `choices[0].message.tool_calls[]`，逐个执行后以 `{role:"tool", tool_call_id, content}` 回灌，循环直至模型不再请求工具或调用终止工具。
- **终止工具**：约定一个 `finish({summary})` 作为显式结束信号，避免模型无限调用；同时设硬上限（本项目 8 轮）。
- **只读先行**：系统提示词要求先 `list_habits` 再决策，显著降低重名/重复创建。
- **客户端守门**：LLM 的每次写操作都要在客户端校验（字段长度、枚举、id 存在性、重名），校验失败以 `content` 返回错误让模型自行改正，而非直接抛异常终止。
- **幂等与可撤销**：记录本次会话产生的 `createdHabitIds` / `archivedHabitIds` / 被改字段，提供撤销；撤销 = 删除新建项 + 恢复归档项，与「积分可逆」同一原则。
- **降级链**：原生 `tool_calls` → 解析回复文本中的 JSON（`{name,emoji,note}`）→ 纯本地兜底文案；任一层可用都不阻塞用户。
- **Tauri 落点**：请求走 `@tauri-apps/plugin-http` 的 `fetch`，能力 scope 形如 `{ "identifier": "http:default", "allow": [{ "url": "https://*" }] }`（scope 用 URL Pattern；base URL 可配置时给通配，否则会静默失败）。

## 16. 需求定稿：REQ-02 清单排序修复与自定义属性

### 16.1 清单拖拽排序失效（缺陷）
- **根因**：Tauri 窗口配置 `dragDropEnabled` 默认为 `true`，会在 Windows 上拦截 WebView 内的 HTML5 拖放（官方 schema 原文：*Disabling it is required to use HTML5 drag and drop on the frontend on Windows*）。
- **修复**：`src-tauri/tauri.conf.json` 窗口加 `"dragDropEnabled": false`；拖拽代码补齐 `dataTransfer` 交互；并额外提供 ↑/↓ 按钮，保证在任何环境下都能调序。
- **经验（可复用）**：凡 Tauri + WebView 内需用 HTML5 拖放，必先关 `dragDropEnabled`。

### 16.2 每条习惯的自定义属性（新增 habits 列）
| 列 | 含义 | 默认 |
|----|------|------|
| `hp_max` | 血量上限（仅缺点/ Boss） | 100 |
| `hp_step` | 每次成功避开扣血（仅缺点） | 3 |
| `points` | 每次完成打卡得分（优缺点通用） | 2 |

- 三者在「清单 → ⚙️ 更多设置」中逐条自定义，新建时带默认值。
- `points` 为**权威值**；设置页的「每次打卡」降级为**新习惯默认值**（改设置不再回溯影响已有习惯）。
- 积分防刷分原则不变：取消打卡仍按实际得分/扣血逆转（可逆、对账）。

## 17. 需求定稿：REQ-03 拖拽与交互修复

### 17.1 拖拽排序（HTML5 DnD 不可靠 → 指针方案）
- 实测：即使 `dragDropEnabled:false`，WebView2 下 HTML5 `draggable` 仍未能稳定触发。
- **定案**：改用 **Framer Motion `Reorder`**（基于 pointer 事件，不经 OS 拖放）。
  - `Reorder.Group` + `Reorder.Item`；`dragListener={false}` + `useDragControls`，仅把手启动拖动，避免与按钮/输入冲突。
  - 拖动期间只改本地顺序，去抖后才写库（`reorderHabits`）并 `refresh`。
  - 保留 ▲▼ 按钮作为无障碍备选。
- 经验：Tauri/WebView2 内的列表拖拽宁用 pointer 方案，勿依赖 HTML5 DnD。

### 17.2 已完成项无法取消（Boss 已击败）
- 根因：`BossCard` 的 `onClick={() => !defeated && onToggle()}`——一旦 HP 归零，不管是否今日已打卡都不能再点，无法取消。
  （若把 `hp_step` 设大，一次打卡即击败，立即无法取消。）
- 修复：允许「**今日已打卡** 且 已击败」时取消（`canToggle = !defeated || done`）；取消后回血即不再击败。

### 17.3 打卡刷新延迟
- 根因：一次打卡约 15 次串行 IPC；且 `reconcileWeeklyBonus` / `isSevenDayFull` 各做一次**全库 `exportAll()`**。
- 修复：
  1. 新增 `repo.sumPointsByDate(date, reasons)` 定向查询，取代 `exportAll` 对账；
  2. `isSevenDayFull` 改用 `listCheckinsBetween(近7天)`；
  3. **乐观更新**：点击后立即在 store 本地标记打卡状态，再静默完成积分/血量/对账，界面无需等待。
- 新约定：**打卡类交互一律乐观更新**，后台再对账。
