### 重要经验（已记入规范）
- **Windows spawnSync ENOENT 的误导性**：报 cmd.exe ENOENT 时，真因往往是 **cwd 不存在**（本项目：脚本在 scripts/ 下，resolve(__dirname,'advance-retreat') 拼成了 scripts/advance-retreat）。排查先验 cwd！
- Node 24 spawnSync 禁止直接 spawn .cmd/.bat（EINVAL），须 shell:true
- execSync 在 Windows 永远走 shell；shell:false 不生效
- 复制正在运行的 exe 会 EBUSY，部署脚本前应先结束进程
- build-and-deploy.mjs 已修复路径解析并以 spawnSync+shell:true 实现

## 2025-09-25（续6）— 防刷分逻辑修复与实测

### 发现并修复的缺陷
- 原「连续7天全勤」奖励用「当日是否已有该记录」判重：取消打卡时撤销了 -10，但重新打卡时因记录仍存在而不再发放 → **净亏10分**。
- 改为**对账式幂等逻辑** `reconcileWeeklyBonus()`：比对「今日应得净额」与「今日已发放净额（含撤销项）」，只补差额/只扣超额。可逆且不会重复发放。

### 实测验证（真实窗口 + 直读SQLite）
- 打卡「有氧无氧锻炼30min」：积分 20 → 22，checkins 0 → 1，流水 +2
- 再取消：积分 22 → 20，checkins 1 → 0，流水新增 `-2 取消打卡「…」`
- **净变化 0，确认无法刷分**；满分日奖励与7天全勤奖励均按同一原则可逆扣回
- 测试后已清除测试流水，用户数据还原为 7 条流水共 20 分、0 打卡
