# REQ-02 执行计划：清单排序修复 + Boss/积分自定义

> 需求来源：用户 2026-09-25（见 `docs/规范.md` 第 13/16 节）
> 可执行计划：现状差距 → 技术设计 → 任务清单 → 验收。完成后做文档对齐（规范 13.3）。

---

## 一、需求复述（用户原话）

1. **排序不可用**：按住拖拽后无法拖动。
2. **无法自定义血量**（Boss 血量上限）。
3. **无法自定义每次完成扣掉的血量**（每次避开扣血）。
4. **无法自定义每个优缺点完成后得到的加分**（每条习惯的打卡得分）。

## 二、现状与差距

| 事项 | 现状 | 差距 |
|------|------|------|
| 清单拖拽排序 | ⚠️ 代码已写，但 Tauri `dragDropEnabled` 默认 true 拦截 Windows 上 HTML5 拖放 → 完全拖不动 | 关配置 + 补 dataTransfer + 加 ↑↓ 兜底 |
| 血量上限 | ❌ 硬编码 100（`Math.min(100, hp)`、`hp + 3`） | 新增 `hp_max` 列并可编辑 |
| 每次扣血 | ❌ 硬编码 3（`Math.max(0, h.hp - 3)`） | 新增 `hp_step` 列并可编辑 |
| 每次加分 | ⚠️ 仅全局设置 `points_per_checkin` | 新增 `points` 列（每条独立），全局降级为「新习惯默认」 |

## 三、技术设计

### 3.1 数据库迁移（db.ts，兼容老库）
```sql
ALTER TABLE habits ADD COLUMN hp_max  INTEGER NOT NULL DEFAULT 100;
ALTER TABLE habits ADD COLUMN hp_step INTEGER NOT NULL DEFAULT 3;
ALTER TABLE habits ADD COLUMN points  INTEGER NOT NULL DEFAULT 2;
```
- 新装库 SCHEMA 同步加列。
- 老库迁移时把 `points` 回填为当时的全局 `points_per_checkin`，避免行为突变。
- 检测方式沿用现有 `PRAGMA table_info(habits)` + `names.has(...)`。

### 3.2 类型与数据层
- `types.ts`：`Habit` 增 `hp_max` / `hp_step` / `points`。
- `repo.ts`：`createHabit` 接受并写入三字段；`exportAll` / `importAll` 补三列（导入兼容缺失字段，缺省 100/3/2）。

### 3.3 打卡逻辑（Today.tsx）
- 加分：`per = h.points`（权威），不再读全局。
- 缺点扣血：`h.hp - h.hp_step`，下限 0；取消回补：`min(h.hp_max, h.hp + h.hp_step)`。
- 满分日 / 连续 7 天全勤奖励保持不变（全局）。

### 3.4 Boss 显示（BossCard.tsx / Habits.tsx）
- 血条按 `hp / hp_max` 计算宽度；文案 `HP {hp}/{hp_max}`；击败提示 `削弱 -{hp_step} HP`。

### 3.5 编辑入口（Habits.tsx 的 ⚙️ 对话框）
- 缺点：`血量上限` / `每次避开扣血` / `每次加分`。
- 优点：`每次加分`。
- 校验：数值 > 0（扣血可 0 表示不减血）。
- 新建时默认：hp_max=100、hp_step=3、points=全局 `points_per_checkin`。
- 顺带重构：`HabitForm` 用 `key` 强制重挂载替代原「渲染期 setState」重置写法，并加载全局默认分。

### 3.6 拖拽排序（Habits.tsx）
- `tauri.conf.json` 窗口 `"dragDropEnabled": false`。
- `onDragStart` 补 `e.dataTransfer.setData("text/plain", id)` 与 `effectAllowed="move"`；`onDragOver` 设 `dropEffect="move"`。
- 每行增加 ↑ / ↓ 按钮（同栏内上移/下移），保证在任何环境可排序。

## 五、验收标准

1. 清单页按住拖拽可正常调序并持久化；↑↓ 按钮同样可调序。
2. 缺点可自定义血量上限、每次扣血；打卡/取消按自定义值生效、可逆。
3. 每条优点/缺点可自定义每次加分；打卡按自定义值入账、取消按同值扣回。
4. 老库自动迁移不丢数据，points 回填为原全局值。
5. `npm run build` 类型通过；`npm run deploy` 出包。

## 六、风险

| 风险 | 应对 |
|------|------|
| 关 dragDropEnabled 影响文件拖入 | 本应用无文件拖入需求，可接受 |
| 自定义值越界/为负 | 客户端 clamp（hp_max≥1、hp_step≥0、points≥0） |
| 老库 points 回填 | 迁移时一次性回填为全局值 |
