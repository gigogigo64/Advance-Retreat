# REQ-03 执行计划：拖拽与交互修复

> 需求来源：用户 2026-09-25 反馈（见 `docs/规范.md` 第 13/17 节）
> 三个问题：①拖拽仍不能移动 ②今日无法取消打卡 ③页面刷新延迟。

---

## 一、现状与根因

| 问题 | 根因 |
|------|------|
| 拖拽仍无法移动 | WebView2 下 HTML5 `draggable` 仍不稳定触发（`dragDropEnabled:false` 不足） |
| 今日无法取消打卡 | `BossCard` 的 `onClick={() => !defeated && onToggle()}`：HP 归零后彻底不可点（含取消） |
| 刷新延迟 | 打卡路径 ~15 次串行 IPC；`reconcileWeeklyBonus` + `isSevenDayFull` 各做一次全库 `exportAll()` |

## 二、技术设计

### 2.1 拖拽改指针方案（Framer Motion Reorder）
- 清单两栏各用 `Reorder.Group` + `Reorder.Item`；`dragListener={false}` + `useDragControls` 仅把手启动。
- 每栏维护本地有序 state（`goodItems`/`badItems`），由 `habits` 同步；拖动只改本地，去抖 600ms 后 `reorderHabits` + `refresh`。
- 保留 ▲▼ 按钮。
- 移除全部 HTML5 DnD 代码（dragId/overId/commitReorder/onDragXxx）。

### 2.2 允许取消已打卡的击败 Boss
- `canToggle = !defeated || done`；`whileTap/whileHover` 同步跟随。

### 2.3 打卡乐观更新 + 对账降本
- store 增 `applyCheckin(habitId, date, done)`，点击后立即本地更新。
- `repo.sumPointsByDate(date, reasons)` 定向查询取代 exportAll。
- `isSevenDayFull` 用 `listCheckinsBetween(近7天)`。

## 四、验收标准

1. 清单页按住 ⠿ 可直接拖动排序并持久化；▲▼ 亦可。
2. 今日页已打卡项再次点击可取消（含已击败的 Boss），积分/血量正确回退。
3. 打卡后勾选状态**立即**变化，无明显延迟。
4. `npm run build` 通过；`npm run deploy` 出包。

## 五、风险

| 风险 | 应对 |
|------|------|
| Reorder 与内部按钮/输入冲突 | `dragListener={false}` 仅在把手启动 |
| 去抖期间下次拖动 | 定时器重置，仅持久化最后顺序 |
| 乐观更新与库不一致 | 后台 `refresh()` 对账覆盖 |

## 六、执行结果

**改动文件**：`store.tsx`（applyCheckin）/ `repo.ts`（sumPointsByDate）/ `Today.tsx` / `BossCard.tsx` / `Habits.tsx`

- 拖拽：彻底移除 HTML5 DnD，改用 `Reorder.Group` + `Reorder.Item` + `useDragControls`（仅把手启动）；去抖 500ms 持久化；保留 ▲▼。
- 取消：`canToggle = !defeated || done`，已击败但仍可取消今日打卡。
- 延迟：乐观更新（点击即变）+ `sumPointsByDate` 定向查询 + 近7天定向查询取代两次全库 `exportAll`。

**验证**：`npm run build` 类型通过；`npm run deploy` 出包部署。拖拽需在真实窗口人工确认（沙箱无法模拟）。
